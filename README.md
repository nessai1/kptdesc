# КПТ-дневник

Десктопное приложение для ведения дневника когнитивно-поведенческой терапии: ежедневный чекап базовых потребностей, записи «ситуация → эмоции → мысль → альтернативная мысль», список заботы о себе и недельный отчёт для психолога.

Реализовано по дизайн-handoff `KPT.zip` (`design_handoff_kpt_diary`).

## Стек

- Tauri 2 (Rust) — окно приложения, хранение данных, экспорт отчёта
- React 19 + TypeScript + Vite 8 — интерфейс
- Шрифты Lora и Manrope поставляются вместе с приложением (`@fontsource`), сеть не требуется

## Запуск

```bash
npm install
npm run tauri dev      # запуск в режиме разработки
npm run tauri build    # сборка дистрибутива
npm test               # тесты фронтенда
cargo test --manifest-path src-tauri/Cargo.toml   # тесты Rust
```

## Сборка под Windows

Локальная кросс-сборка с macOS требует MSVC-тулчейна, поэтому Windows-версия собирается в GitHub Actions: workflow `.github/workflows/build.yml` запускается на каждый push в `master` и вручную (`gh workflow run build.yml`).

Сборка выполняется на `windows-latest` и публикует артефакты:

- `kpt-diary-windows-installer` — установщик NSIS (`*-setup.exe`);
- `kpt-diary-windows-msi` — установщик `.msi` (собирается дополнительно, не блокирует сборку);
- `kpt-diary-windows-portable` — портативный `.exe`, запускается без установки.

Скачать последнюю сборку:

```bash
gh run download --name kpt-diary-windows-installer
```

Для Windows имя продукта переопределено на ASCII (`KPT Diary`) в `src-tauri/tauri.windows.conf.json`: WiX не собирает MSI с кириллицей в имени файла. Заголовок окна и весь интерфейс остаются на русском, папка данных не меняется — она привязана к идентификатору приложения.

Приложение не подписано сертификатом Windows, поэтому при первом запуске SmartScreen покажет предупреждение: «Подробнее» → «Выполнить в любом случае». Для работы нужен WebView2 Runtime — он встроен в Windows 11 и в актуальные сборки Windows 10, установщик NSIS при необходимости доустановит его сам.

Данные на Windows хранятся в `%APPDATA%\com.kptdesc.diary`.

## Хранение данных

Данные лежат в папке приложения (`~/Library/Application Support/com.kptdesc.diary` на macOS):

- `diary.json` — записи дневника;
- `settings.json` — настройки.

Схема `diary.json` совпадает со схемой из handoff:

```json
{
  "2026-07-31": {
    "checkup": { "day": { "0": true }, "eve": { "3": true } },
    "cbt": [
      {
        "happened": "…",
        "thought": "…",
        "alt": "…",
        "emotions": [{ "name": "Тревога", "intensity": 80 }]
      }
    ],
    "care": [{ "what": "…", "time": "14:30" }]
  }
}
```

Ключи дат — локальные (`YYYY-MM-DD`), без перевода в UTC. Индексы в `checkup` — позиции пунктов в списке из девяти базовых потребностей. Запись файлов атомарная: данные сначала пишутся во временный файл, затем переименовываются поверх основного.

Сохранения выстраиваются в очередь и склеиваются: пока идёт запись, в очереди остаётся только последнее состояние, поэтому быстрые правки не могут попасть на диск в обратном порядке.

Если `diary.json` не читается (повреждён или недоступен), приложение показывает экран с ошибкой и не даёт редактировать записи — иначе первое же изменение перезаписало бы файл, который ещё можно восстановить вручную. Ошибка чтения `settings.json` не блокирует работу: используются значения по умолчанию, файл перезаписывается только при явном сохранении настроек.

## Выгрузка отчёта в PDF

Кнопка «Выгрузить в PDF за неделю» открывает экран отчёта за выбранную неделю. Кнопка «Сохранить в PDF» формирует самодостаточный HTML-файл (стили и шрифты встроены), кладёт его во временную папку и открывает в браузере по умолчанию — там отчёт сохраняется в PDF через диалог печати.

Печать выполняется в браузере, потому что WKWebView (движок окна на macOS) не предоставляет диалог печати. Экран отчёта в приложении и выгружаемый файл используют один и тот же CSS, поэтому предпросмотр и печатная версия совпадают. Поля страницы — 0.6in, формат листа выбирается в диалоге печати.

## Настройки

Доступны по кнопке с шестерёнкой в шапке:

- показывать ли подсказки под пунктами чекапа;
- список эмоций (через запятую; вариант «?» добавляется всегда);
- имя клиента для шапки отчёта.

## Структура

```
src/                     интерфейс
  components/            карточки дневника и диалог настроек
  report/                экран отчёта, его стили и сборка HTML для печати
  dates.ts               работа с датами и неделями
  useDiary.ts            состояние дневника и сохранение на диск
src-tauri/src/           Rust: команды, хранилище, экспорт отчёта
scripts/generate-icon.py генерация app-icon.png (исходник иконки приложения)
```

Иконки приложения собраны из `app-icon.png`. Чтобы пересобрать их после изменения исходника:

```bash
python3 scripts/generate-icon.py   # создаёт app-icon.png
npx tauri icon app-icon.png -o src-tauri/icons
```

## Отличия от прототипа

- Хранилище — JSON-файлы в папке приложения вместо `localStorage`: данные не зависят от состояния WebView и их можно скопировать или включить в резервную копию.
- Переход к отчёту — смена экрана внутри приложения вместо отдельной страницы с параметром `?week=`.
- Настройки (`showHints`, `emotionList`, `clientName`) в прототипе задавались как свойства компонента; в приложении для них добавлен диалог настроек.
- Форма новой записи очищается при переключении дня, чтобы начатый текст не попал в другую дату.
